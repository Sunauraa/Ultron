Ultron

Each morning, tell Claude Code to apply to the jobs published in the last 24 hours. It finds them on the job boards, fills each application from your answers and resume, and leaves it for you to check, or sends it once you trust it.

  1. The first days: approval modeEvery form is filled and left open in Chrome. You check it and press Submit. Fix answers.md and your filters as you go.
  2. Then: autoSet auto_submit = true. Forms filled only from your answers are sent. Any answer the agent wrote itself (a "Why us?") is still held for you, unless you allow that too.
  3. Questions it can't answerA required question your answers don't cover is never guessed. Claude asks you in the chat, saves your answer, and the job is retried.

How it works

  1. FindYou name roles, not companies. Claude searches the web once a day for companies hiring for them, and every company found is kept. Ultron then reads all their public job lists (Greenhouse, Lever, Ashby, Workable, Recruitee, Teamtailor, Personio, BambooHR, Gem), with no LLM.
  2. FilterYour titles and places, published in the last 24 hours, never applied to before. A posting with no date counts only when it newly appeared.
  3. OpenOn the company's own site when the board names it there, with the board's form as the fallback.
  4. FillUltron pre-fills everything answers.md and your resume cover, and handles pop-ups with a tiny on-device model. Claude fills the rest.
  5. Review and sendClaude checks every field against where its value came from. Ultron sends only when config allows, and never with an empty required field, an error, or a captcha up.
  6. LogEvery job lands in applied.csv as ready, submitted, needs_info, needs_human or skipped, and Claude tells you what to do with each.

Why a separate browser

A general browser tool sends the model the whole page after most actions. Ultron sends a short numbered list of the fields still to fill, already pre-filled where your answers apply. That is where the turns and tokens above go.

What code decides, not the model

  • The agent on each job gets only Ultron's tools: no shell, files or web.
  • Hidden fields, the way pages steal what agents type, are never filled.
  • No made-up email or phone: values not in your answers are refused or flagged.
  • No account is created; sign-in walls and bot checks go to you.
  • LinkedIn, Indeed and similar sites are never opened.

Set up

You need Claude Code, logged in; Python 3.11+; and Chrome. Then, once:

git clone https://github.com/Sunauraa/Ultron && cd Ultron/autoapply
pip install playwright mcp pypdf reportlab numpy && playwright install chromium
cp config.example.toml config.toml      # your roles and places; auto_submit = false to start
cp answers.example.md answers.md        # your answers, one "Question: answer" per line
cp ~/path/to/resume.pdf resume.pdf

Each morning:

cd Ultron/autoapply && claude
> submit job applications to those that just published within 24 hours

Prefer no chat? ./run.sh --hours 24 does the same from cron. The full guide is in the README.

What's tested, and what isn't

Tested

  • Real Claude Code: one application through Ultron, the baseline above, and the morning request end to end.
  • 36 application pages recorded from real sites and replayed offline: the boards above and three company sites that show Greenhouse in a frame.
  • The whole pipeline on 31 of them, in approval and auto mode, with a local model standing in for Claude Code: 62 jobs, none lost or run out of turns.
  • Offline test suites for Ultron, the pipeline and the pop-up model.

Not yet

  • Sending a real application on a live site: every page so far was a recording.
  • Workday, iCIMS, Oracle and SmartRecruiters: detected and handed to you, never filled.
  • Codex in place of Claude Code.
  • Whether applying on a company's own page gets more replies: it lands in the same applicant-tracking system.
